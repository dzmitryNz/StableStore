# Интеграция со spareparts

[spareparts](https://github.com/dzmitryNz/spareparts) — собственный сервис учёта запасов: приходы, расход,
места хранения, сроки годности по партиям (расход идёт с ближайшего срока) и отчёт «что скоро истекает».
Скрипт `seed.mjs` готовит файлы данных для **новой** копии сервиса из CSV в `../grocy/`.

## Запуск

```sh
node integration/spareparts/seed.mjs --people 2.6 --months 3 --out ~/food-data
```

- `--people` — сколько «взрослых»: взрослый 1.0, ребёнок 10-15 лет 0.8, 5-10 лет 0.6, до 5 лет 0.35.
  Семья из 2 взрослых и ребёнка 8 лет: `2.6`.
- `--months` — на сколько месяцев запас. `min_qty` («Alert below») = норма на 1 взрослого в месяц × people × months.
- `--out` — папка данных (`DATA_DIR` сервиса). Если в ней уже есть данные, скрипт ничего не пишет;
  `--force` перезаписывает все пять файлов, **включая журнал операций**.
- `--src` — другая папка с CSV в формате `../grocy/` (по умолчанию `../grocy/`).

Что получается:

- `items.csv` — 50 продуктов. ID — транслит названия (`Рис белый` → `RIS-BELYY`), единицы `kg`, `l`, `can`, `pack`…
- `categories.csv` — группы продуктов, `locations.csv` — места хранения (без вложенности, её можно задать в интерфейсе).
- `moves.csv`, `tasks.csv` — пустые: остатки появятся, когда вы внесёте реальные приходы со сроками с упаковок.

Затем запустите сервис на этой папке: `DATA_DIR=~/food-data PORT=8020 node server.js` (из папки spareparts).

## Тесты

```sh
node --test 'integration/**/*.test.mjs'
```

Последний тест прогоняет скрипт на настоящих CSV из `../grocy/`, поэтому он же проверяет их целостность
(ссылки на места, группы, единицы и уникальность ID).
